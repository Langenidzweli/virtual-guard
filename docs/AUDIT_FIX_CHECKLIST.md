## Running the checks again

From `frontend`, run `npm.cmd test`, `npm.cmd run build` and `npm.cmd run lint`.

From `ai-service`, run `venv313\Scripts\python.exe -X utf8 -m unittest discover -s tests` (or the equivalent Python in your environment).

Backend unit tests use `mvn test`. To include `AuditDatabaseTest`, supply these environment variables before running Maven:

- `AUDIT_DB_URL`: a PostgreSQL JDBC URL with no existing query string, e.g. `jdbc:postgresql://localhost:5432/virtualguard`.
- `AUDIT_DB_USER` and `AUDIT_DB_PASSWORD`: credentials permitted to create a temporary schema in that database.

Without those variables, only the database-specific tests are skipped. Local `target` files were locked during this session, so Maven used an isolated output directory via `-Dvirtualguard.build.directory=.../output/backend-audit-build`.

To repeat the browser checks from the repository root:

1. `npm.cmd install --prefix output/browser-check --no-audit --no-fund playwright`
2. Run the frontend on `127.0.0.1:5175` (`npm.cmd run dev -- --host 127.0.0.1 --port 5175` from `frontend`).
3. `node frontend/tests/browser-audit.mjs`

The browser script uses installed Microsoft Edge and a generated black test clip in `frontend/tests/fixtures/clip.mp4`; it does not modify application records.

## Applying the changes locally

Restart Spring Boot and FastAPI together, then reload the frontend. The callback protocol now requires `attempt_id` on analysis requests and `attemptId` on progress/final callbacks. Mixing old and new service processes will fail validation. Existing PROCESSING rows without heartbeat/attempt metadata become FAILED on the recovery scan and can be retried.

The existing Hibernate `ddl-auto: update` configuration adds the nullable user link, credential generation, job metadata and JSONB notes column at backend startup. This work does not reset application tables. A new guard account needs a password of at least 12 characters; adding a profile for an existing login preserves that login's password. Deactivated users must log in again after reactivation.

Lease settings are Spring properties: `app.jobs.lease-seconds` (120), `app.jobs.max-duration-seconds` (7200), and `app.jobs.recovery-interval-ms` (30000). Size the maximum duration for the videos and hardware being used. Inference output quality and the statistical calibration of short-window behavior predictions are separate from these integration fixes.
